# OPEN_QUESTIONS — вопросы к пользователю

Формат: у каждого вопроса есть **контекст**, **что сделано или будет сделано по умолчанию** и **что он блокирует**. Пока ответа нет, работа идёт по варианту по умолчанию, который проще всего переключить конфигурацией. Ответы можно вписывать прямо сюда.

Статусы: 🔴 блокирует работу в контуре или критерий этапа · 🟡 влияет на структуру, есть разумное значение по умолчанию · ⚪ уточнение.

Подробности находок — в `REPO_NOTES.md`.

## A. Среда и доступы

### Q1 🔴 .NET SDK в облачной сессии агента
- **Контекст:** в контейнере нет `dotnet`. `dotnet-install.sh` по `global.json` получает 403: политика сети сессии блокирует `builds.dotnet.microsoft.com` и `ci.dot.net`. В apt (Ubuntu 24.04 `noble-updates`) есть `dotnet-sdk-10.0` 10.0.112 — он подходит под `global.json` (`rollForward: latestMajor`), но установку этим путём вы отклонили.
- **Вопрос:** как ставить SDK? Варианты:
  1. добавить `builds.dotnet.microsoft.com` (и `ci.dot.net`) в разрешённые домены окружения — это меню облачного окружения в заголовке сессии → Edit → Network access;
  2. разрешить apt-пакет `dotnet-sdk-10.0`;
  3. setup-скрипт окружения или SessionStart-хук, который ставит SDK при старте.
- **По умолчанию:** ничего не устанавливаю. Этап 0 сборки не требует.
- **Блокирует:** критерий Этапа 1 «решение собирается, тесты зелёные» — без SDK его нельзя проверить в сессии.

### Q2 ⚪ Как подаются секреты в контуре
- **Контекст:** в `appsettings.json` плейсхолдеры, `.env` в `.gitignore`, user-secrets не настроены.
- **Вопрос:** переменные окружения (`Opensearch__Password`, `KnowledgeService__...`), `.env` через docker-compose или что-то ещё?
- **По умолчанию:** стандартные переменные окружения .NET. В `appsettings.json` — только плейсхолдеры. В `RUNBOOK.md` — список нужных переменных.

### Q3 ⚪ Права на создание индексов `ks-*`
- **Вопрос:** хватает ли прав у учётки из секции `Opensearch` на создание индексов и алиасов с префиксом `ks-`? Или для KS будет отдельный пользователь?
- **По умолчанию:** KS использует существующий `IOpenSearchClient` из проекта `Opensearch` и те же учётные данные. Если нужен отдельный пользователь — добавлю отдельную регистрацию клиента.

## B. Внешние системы (без ответа — только фейки и заглушки)

### Q4 🔴 Контракт сервиса FRIDA
- **Контекст:** в репозитории нет клиента, контракта и URL для FRIDA (есть только упоминание в `readme.md`). По ТЗ 1.3 и 3.1 реальный адаптер пишется только по контракту из репозитория.
- **Вопрос:**
  - где клиент или контракт (другой репозиторий, OpenAPI-спецификация, пример запроса и ответа)?
  - протокол: OpenAI-совместимый `/v1/embeddings`, HF TEI `/embed` или свой?
  - аутентификация, максимальный размер батча, rate limit;
  - отдаёт ли сервис число токенов или признак обрезки входа?
- **По умолчанию:** `IEmbeddingClient` + детерминированный фейк для тестов + адаптер-заглушка: `check` пишет «FAIL: адаптер FRIDA не настроен (нет контракта)». Если подтвердите стандартный протокол (OpenAI `/v1/embeddings` или TEI `/embed`), сделаю адаптер под него с выбором формата в конфиге. Размерность — `KnowledgeService:Embeddings:Dimensions` (1536); `check` сверяет её с фактическим ответом.
- **Блокирует:** реальную индексацию и поиск в контуре (Этапы 3–4). Разработку на фейках не блокирует.

### Q5 🔴 Добавляет ли сервис FRIDA префиксы `search_query: ` / `search_document: ` сам
- **Контекст:** ТЗ 6.0 требует выяснить это по контракту, а контракта нет.
- **По умолчанию:** префиксы добавляет `IEmbeddingClient` — флаг `KnowledgeService:Embeddings:AddPrefixes = true`. Добавление идемпотентно: если текст уже начинается с префикса, второй раз он не добавляется (тест «ровно один раз»). Если окажется, что сервис добавляет префиксы сам, — поставить `false` и переиндексировать.

### Q6 🔴 Индекс вики в OpenSearch
- **Контекст:** в репозитории нет ни имени индекса, ни маппинга, ни модели статьи. Единственная ссылка на индекс — `Opensearch:Index` = `"index"` (плейсхолдер).
- **Вопрос:**
  - имя индекса или алиаса вики; `Opensearch:Index` — это он?
  - вывод `GET <index>/_mapping` и 1–2 обезличенных документа;
  - хранится ли **полный HTML** статьи или только текст / чанки?
  - поле даты изменения, URL статьи;
  - один документ = одна статья или статья уже порезана на чанки?
  - есть ли признак удаления или архивности?
  - есть ли HTTP API вики как альтернатива?
- **По умолчанию:** `IWikiSource` читает существующий индекс только на чтение (PIT + `search_after`). Имена полей (`Id`, `Title`, `Url`, `Html`, `UpdatedAt`, `Access`) задаются в `KnowledgeService:Sources:Wiki:Fields`. Если в индексе нет HTML, парсер работает с тем, что есть, и я записываю ограничение.
- **Блокирует:** Этап 3 в контуре. Разработку парсера и чанкинга на синтетическом HTML не блокирует.

### Q7 🔴 Оргструктура: индекс или API оргсервиса
- **Контекст:** в репозитории нет ни клиента оргсервиса, ни индекса оргструктуры.
- **Вопрос:**
  - имя индекса и `_mapping` + примеры записей организации, подразделения и сотрудника (обезличенные);
  - как различаются типы и какие у них id;
  - где полное и краткое наименование, аббревиатура, родитель, руководитель;
  - ФИО хранится частями или одной строкой?
  - есть ли HTTP API оргсервиса (и клиент к нему) для живых данных (`GetUnitAsync`)?
- **По умолчанию:** `IOrgSource` (включая `GetUnitAsync`) читает из индекса оргструктуры, поля — в конфигурации. ТЗ 4.3 допускает это, если API нет.
- **Блокирует:** Этап 2 в контуре. Генерацию и нормализацию алиасов (чистые функции) не блокирует.

### Q8 🟡 Сервер Gemma: structured output и режим размышлений
- **Контекст:** Gemma подключена как OpenAI-совместимый эндпоинт `{Url}/v1` через `IChatClient` (`Assistant/DependencyInjection.cs`). Structured output, temperature и thinking в репозитории не используются.
- **Вопрос:**
  - какой сервер отдаёт модель: vLLM, Ollama, llama.cpp, TGI или другой?
  - поддерживает ли он `response_format: { type: "json_schema" }`?
  - как отключается режим размышлений у Gemma 4 на этом сервере (параметр запроса, `chat_template_kwargs`, отдельное имя модели)?
  - нужен ли реальный API-ключ?
- **По умолчанию:** `ChatResponseFormat.ForJsonSchema(...)` + валидация ответа по схеме + один повтор с текстом ошибки (ТЗ 6.2.9). Режим задаётся `KnowledgeService:Llm:StructuredOutput` = `JsonSchema` / `JsonObject` / `PromptOnly`. `Llm:Thinking` пока только передаётся в конфигурацию; способ отключения реализую после ответа. `check` делает тестовый JSON-запрос и показывает, что вернулось.

### Q9 ⚪ Реранкер
- **Вопрос:** есть ли реранкер в контуре? URL, формат (HF TEI `/rerank` или другой), модель.
- **По умолчанию:** адаптер TEI `/rerank`, `KnowledgeService:Reranker:Enabled = false`. `check` для выключенного реранкера пишет «SKIP».

### Q10 🟡 Версия OpenSearch и kNN
- **Контекст:** версия сервера в репозитории не видна, клиент — `OpenSearch.Client 2.1.0`. От версии и движка зависит, поддерживается ли efficient filtering в kNN: для `lucene` — с 2.4, для `faiss` — с 2.9.
- **Вопрос:** версия кластера, установлен ли k-NN плагин, какие движки разрешены?
- **По умолчанию:** движок `lucene` (`KnowledgeService:OpenSearch:KnnEngine`), фильтр внутри `knn`-запроса. Альтернатива — post-filter с увеличенным `k` через `KnowledgeService:Retrieval:KnnFilterMode` = `Efficient` / `PostFilter`. `check` печатает версию кластера и наличие плагина `knn`.

## C. Данные для оценки

### Q11 🔴 Golden set
- **Контекст:** в репозитории golden set не найден.
- **Вопрос:**
  - путь или файл, формат (JSON / JSONL / CSV / XLSX), объём;
  - есть ли категории;
  - как заданы ожидаемые статьи — id, URL или заголовки?
  - есть ли ожидаемые сущности и подстроки ответа?
- **По умолчанию:** загрузчик JSONL/CSV с колонками, совпадающими с `GoldenItem` (`id`, `question`, `category`, `expected_doc_ids`, `expected_entity_ids`, `expected_answer_substrings`). Под реальный формат напишу отдельный адаптер. Если категорий нет — эвристические (`attribute` / `howto` / `other`), с пометкой в отчёте.
- **Блокирует:** первый реальный прогон eval (Этап 4 в контуре). Метрики и раннер разрабатываются на синтетике.

### Q12 🟡 Текущий поиск чата (конфигурация `legacy`)
- **Контекст:** в репозитории нет кода текущего поиска (нет ни чата, ни запросов к индексу вики). `LegacySearchAdapter` по ТЗ 9.3 построить не из чего.
- **Вопрос:** где код текущего поиска (другой репозиторий)? Можно ли дать тело запроса, который он отправляет в OpenSearch, или выгрузить его результаты по вопросам golden set?
- **По умолчанию:** `legacy` читает заранее выгруженные результаты из файла (JSONL `{ "question_id", "doc_ids": [...] }`). Если файла нет, конфигурация пропускается с пометкой в `summary.md`. Если дадите тело запроса — воспроизведу его напрямую.

### Q13 ⚪ Права доступа к статьям вики
- **Вопрос:** есть ли у статей ограничения доступа? Как текущий чат их учитывает (по группам пользователя? где взять группы)?
- **По умолчанию:** `KnowledgeService:Access:Enabled = false`, поле `access` в маппингах создаётся (ТЗ 11).

## D. Структура кода

### Q14 🟡 Куда класть новый код (раздел 0, последняя строка)
- **Контекст:** проекты лежат плоско в корне (`Application`, `Assistant`, `Opensearch`, `Web`), у модулей есть парные `*.Contracts`, в `.sln` — папки `Contracts` и `Infrastructure`.
- **По умолчанию:** новые проекты в корне, имена по ТЗ:

  | Проект | Папка решения | Содержимое |
  |---|---|---|
  | `KnowledgeService.Core` | — | модели, порты, чистая логика (нормализация, алиасы, парсинг, чанкинг, grounding, RRF, контекст, метрики), пайплайны индексации и поиска, eval |
  | `KnowledgeService.Infrastructure` | `Infrastructure` | адаптеры: OpenSearch (`ks-*`, источники), LLM поверх `IChatClient`, FRIDA, реранкер, кэш, состояние; `AddKnowledgeService(this IHostApplicationBuilder)` |
  | `KnowledgeService.Contracts` | `Contracts` | DTO HTTP API — по шаблону `X` + `X.Contracts` |
  | `KnowledgeService.Cli` | — | консоль: `check`, `index`, `ingest`, `inspect`, `search`, `eval` |
  | `KnowledgeService.Tests` | — | unit + интеграционные (trait `Category=Integration`, запуск при `KS_INTEGRATION=1`) |

  Отдельного `KnowledgeService.Ingestion` нет: ТЗ 4.1 разрешает держать его внутри Core/Infrastructure.

### Q15 🟡 HTTP API: в существующий `Web` или отдельный хост; нужен ли MediatR
- **Контекст:** `Web` — единственный хост, настроены контроллеры, `/health`, OpenAPI. По `readme.md` репозиторий и есть «сервис интеллектуального поиска». MediatR зарегистрирован, но обработчиков нет.
- **По умолчанию:**
  - эндпоинты раздела 8 — контроллерами в `Web`;
  - `/health` — проверки KS как `IHealthCheck` в уже настроенном конвейере;
  - контроллеры вызывают сервисы KS напрямую, без MediatR: так проще, и CLI использует те же сервисы.

  Если нужен отдельный `KnowledgeService.Api` или обработчики MediatR в `Application` — это обёртка над теми же сервисами, переделка небольшая.

### Q16 🟡 Можно ли минимально поправить `Assistant`
- **Контекст:** `AssistantOptions` не привязаны к конфигурации, и секции для них нет в `appsettings.json`. В таком виде `IChatClient` не сможет работать (см. `REPO_NOTES.md`, раздел 4). `AssistantOptions.ApiKey` игнорируется, ключ захардкожен как `"RandomKey"`.
- **По умолчанию (на Этапе 1):**
  - добавить в `Assistant/DependencyInjection.cs` одну строку `AddOptions<AssistantOptions>().BindConfiguration("Assistant")`;
  - добавить секцию-плейсхолдер `Assistant` в `appsettings.json`;
  - `"RandomKey"` не трогать до вашего ответа.

  Альтернатива — KS регистрирует свой `IChatClient` тем же способом, не трогая `Assistant`.

### Q17 🟡 Новые NuGet-пакеты
- **Контекст:** CPM, `nuget.config` в репозитории нет. `NoWarn NU1803;NU1507;NU1301` намекает на внутреннее HTTP-зеркало NuGet в контуре.
- **Вопрос:** можно ли добавлять пакеты, и доступны ли в зеркале эти?
  - `AngleSharp` — парсинг HTML, ТЗ 6.2.2;
  - `System.CommandLine` — CLI;
  - `Microsoft.Extensions.Hosting` — Generic Host для CLI;
  - `xunit.v3`, `xunit.runner.visualstudio`, `Microsoft.NET.Test.Sdk` — тесты.
- **По умолчанию:** добавляю их через `Directory.Packages.props`. Выбор xUnit v3: встроенный динамический skip (`Assert.SkipUnless`) для интеграционных тестов без лишних пакетов. Snapshot-библиотек (Verify) и FluentAssertions не беру: JSON проверяется через `System.Text.Json.Nodes`. Если какого-то пакета нет в зеркале:
  - `System.CommandLine` → ручной разбор аргументов;
  - xUnit → то, что есть в зеркале (MSTest/NUnit).

### Q18 ⚪ Аутентификация HTTP API
- **Контекст:** в `Web` аутентификации нет.
- **По умолчанию:** без аутентификации, как весь `Web` сейчас (ТЗ 8: «простая заглушка»). `userId`/`groups` в запросе используются только для ACL, если он включён.
